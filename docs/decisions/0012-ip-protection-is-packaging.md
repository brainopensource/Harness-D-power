# ADR-0012: Compiled Packaging Is a Packaging Concern, Not an Architectural One

**Status**: Accepted · **Date**: 2026-08-05 · **Fork**: F12

## Context

One proposal rated a Nuitka-plus-stripped-Rust packaging pipeline "Excelente" for IP
protection, on the basis that the product is intended for commercial enterprise
distribution. The other held that compilation is a speed bump.

The corroborating evidence is unusually direct: the most heavily engineered competitor in
the study set **ships a native Rust binary and still obfuscates only its prompt text**, with
a trivially reversible XOR generated by a build script. A team that compiled everything did
not believe compilation protected the thing they actually cared about.

## Decision

- **Compilation is a speed bump, and IP protection does not shape the architecture.**
- No packaging consideration influences language choice, module boundaries, port design or
  the build for development and evaluation.
- A compiled-distribution pipeline is deferred to a packaging phase, evaluated then on
  distribution requirements alone.

## Consequences

- No build step enters the developer loop or the self-improvement loop for IP reasons.
  ADR-0001 already excludes one for performance reasons; this closes the other route in.
- **The moat is the measured harness** — the lift number on a verified instrument, and the
  work that produced it. That is not a thing a decompiler recovers.

## Reversal Conditions

A specific distribution requirement — a customer contract or a deployment target that
mandates no source on disk — reopens this as a **packaging** decision. It does not reopen
any architectural decision, and this ADR is not a precedent for one.
