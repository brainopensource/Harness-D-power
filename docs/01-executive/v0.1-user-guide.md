# **SAGIHA v0.1 — First Genuinely Useful Release**

> [!NOTE]
> **Product Positioning**: This document defines the capabilities, target user, core workflow, and competitive differentiation for the initial usable release of SAGIHA.

---

## 1. **Target User & Use Case**

* **Target User:** Senior Software Engineers, Maintainers, and Autonomous Engineering Teams working on complex Python codebases.
* **Core Value Proposition:** Deterministic, reproducible, capability-secured automated issue resolution with **zero grader-editing cheating** and **zero API lock-in**.

---

## 2. **What SAGIHA v0.1 Ships With**

1. **Standalone Evaluation Harness (E0 / S0):**
   - Commit-replay benchmark harvester that extracts real bug/fix pairs from repository history.
   - Rigorous A/A noise floor measurement ($\sigma_{\text{noise}}$ at $p < 0.05$) to ensure performance gains are statistically significant.
   - Standalone task runner that can evaluate SAGIHA or third-party agent outputs against pristine, isolated test gates.

2. **Isolated & Sandboxed Execution (S1):**
   - Containerized worktree execution (`Docker`/`Podman`) preventing ungranted writes outside the target workspace.
   - Capability-based authorization (CAR model) with strict policy engine dispatches.
   - Multi-provider model support (Anthropic Claude, OpenAI GPT, Google Gemini) via native SDKs with prompt-caching and thinking block preservation.

3. **AST Retrieval & Diagnostics (S2):**
   - Tree-sitter AST-bounded chunking and hybrid BM25/vector retrieval.
   - Warm LSP supervisor providing instant type and lint feedback to the agent during candidate generation.

---

## 3. **Why Choose SAGIHA v0.1 Over Alternatives**

| Feature / Capability | Standard Coding Assistants (Aider / OpenHands) | SAGIHA v0.1 |
| :--- | :--- | :--- |
| **Test Protection** | Candidate can edit tests to force a pass | **Pristine Injected Test Gate** (`tests_unmodified` hard gate) |
| **Replay & Audit** | Re-executes network/side-effects on replay | **Byte-for-byte cassette record/replay determinism** |
| **Security Perimeter** | Unrestricted local shell or vague sandbox | **Container boundary + Pydantic Capability Grants** |
| **Evaluation Rigor** | Single-run benchmark score (noisy) | **Commit-replay harvester + A/A noise floor baseline** |

---

## 4. **Getting Started with v0.1**

```bash
# 1. Initialize SAGIHA config
sagiha init --config config.toml

# 2. Run an evaluation slice over repository commits
sagiha harvest --repo . --max-commits 20

# 3. Execute a sandboxed task run with record/replay determinism
sagiha run --task "Fix issue #142" --config config.toml
```
